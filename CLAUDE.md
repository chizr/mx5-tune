# MX-5 NB turbo tune — notes for Claude Code

Chris's NB1 MX-5 10th Anniversary (6-speed; built 1.8 BP, **stock pistons**, forged rods, honed and blueprinted; Eight Nine TD04-19T hybrid with 0.41 A/R housing, ME442 ECU, 98 RON). This repo holds the ECU calibration, logs and the worklog. Read `docs/worklog.md` first, starting with **Where things stand (handover)** at the top: current calibration, next steps and what's waiting on Chris. Hardware, change log, findings, open items and reference numbers are below it.

## Layout

- `calibrations/mx5_nb_me442_vN.mecal` — one file per calibration version, so Chris can see exactly which version he is loading into MEITE. Each new version is a **new file** with the next `vN` suffix, copied from the previous version and then edited; never edit an existing version's file. Each version is also a git commit and tag `vN`. Files exist for v7 (what was in the car on 2026-10-07; rollback), v8 and v10 onward; the other early versions are tags only (`git show v3:calibrations/mx5_nb_me442.mecal`).
- `logs/` — ECU logs, renamed `YYYY-MM-DD_HHMM_<source>_<what>.csv`. Index them in `logs/README.md` (calibration tag in the car, fuel age, what was tested).
- `docs/worklog.md` — the living record. `docs/run-sheet_vN.pdf` — printable test plan, generated by `tools/make_runsheet.py`.
- `tools/mecal.py` — read, diff and edit .mecal files. `tools/logtools.py` — load and analyse logs. `tools/vetools.py` — VE coverage, per-cell fuel need and smooth VE fit from closed-loop logs. Plots in `docs/` (`ve_v12_vs_v14.png`, `ve_coverage.png`) were made with matplotlib in the repo's `.venv`.
- `tools/meite_check.py` (Windows, MEITE open) — reads MEITE's screen via UI Automation. `map` writes `docs/meite_layout.md` (which tab holds each driver and table, plus what is only in the left-hand tree); `check FILE` compares every visible driver setting with FILE and checks FILE is the one open (or, when connected, what the ECU holds); `working FILE` diffs MEITE's working copy (`C:\ProgramData\Motorsport Electronics Limited\MEITE\calibs\MEITE_calib.mecal`, rewritten after it reads or burns the ECU) with FILE, tables included. After every burn run both.
- `tools/meite_comms.py` (Windows, MEITE connected) — live ECU frames from MEITE's Comms Log window (~10/s), read in the background (window messages only; no focus, clicks or keys) and trimmed after each read so the box stays small. `watch [SECONDS]` prints decoded fields; `capture SECONDS OUT.txt` records frames alongside a PC log. Offsets live in `tools/meite_frame_map.json`, built by `tools/meite_framemap.py build PCLOG START_ISO FRAMES [--merge]`: only channels that varied in a capture are mapped (110 after a 60 s cold idle on 2026-10-17 and a 20 min drive on 2026-10-18, incl. TPS, boost duty/target, ignition base vs final (= knock retard), VSS, injector duty); add captures with throttle blips and a drive (TPS, knock retard, boost, VSS, EPS status) with `--merge`. Never commit MEITE's DEF files or raw frame dumps (proprietary).
- `tools/dragy.py` (BLE, `bleak`) — records speed from Chris's Dragy GPS at 10 Hz: `record SECONDS OUT.csv`. Saves time, speed, fix, sats, HDOP and course only; position and altitude are dropped at the source and must never be committed. The handshake answer lives in `tools/dragy_secret.py`, which is git-ignored and must stay unpublished. Close the Dragy phone app first; don't pair the Dragy in Windows. Speed unit still to confirm against the ECU's VSS (mph: VSS Mode is pulses per mile; confirmed from gear ratios and the 205/50 R15 tyre). It only ever selects view tabs: never types, edits, saves or touches the ECU. Tables are custom-drawn, so their cells can't be read from the UI. Don't walk the tabs while Chris is using MEITE; ask first.

## Rules for calibration edits

1. Make a new version with `tools/mecal.py`: `load` the previous `_vN` file, edit with `set_param` / `set_cells`, then `save` to the new `_vN+1` path. It replaces values as text and keeps every other byte, including CRLF line endings. Never re-serialise the XML or reformat the file.
2. Before committing, run `python3 tools/mecal.py diff calibrations/mx5_nb_me442_vN.mecal calibrations/mx5_nb_me442_vN+1.mecal` and check that only the intended values changed. Report that diff to Chris.
3. One logical change set per commit, tagged `vN`. Add rows to the change log table in `docs/worklog.md` in the same commit (tag, area, setting, before, after, why).
4. Chris burns calibrations himself in MEITE after spot-checking. Never claim a version has been driven until he says so.
5. Some driver settings repeat a name: `EPS: Oil` has two `Enabled` params (temperature, then pressure → `occurrence=1`).
6. 2D tables are flat, row-major: index = row × cols + col. Rows are load (MAP kPa, `input_1`), columns are rpm (`input_0`).

## Safety stance

- Stock pistons: failures are ring lands from detonation. Low-rpm, high-load knock is the main risk. On the hybrid, knock control fires on cyl 3 (and 2) at 2,500–3,600 rpm × 90–130 kPa; some cyl 3 readings are noise (an event at 46 kPa / 2% TPS), so real knock and noise are mixed until det cans on a dyno separate them.
- Closed loop stays off on boost (max 105 kPa); fix boost fuelling in the VE table instead.
- Don't raise boost targets or add timing without log evidence. Prefer removing timing over adding it. Keep over-boost cut, lean, oil and knock protection enabled.
- Treat numbers from forums or guesses as approximate and label them. Recommend dyno with det cans for final timing.
- Road testing: full-throttle pulls belong on a closed road, track or dyno.

## Working with logs

- Load with `tools/logtools.load()` (pandas `index_col=False`; data rows end with a trailing comma and PC-log headers have leading spaces).
- 10 Hz typical. Useful commands: `logtools.py summary|lambda|knock|idle LOG`.
- Per-cylinder knock: compare each cylinder against its own light-load baseline (`knock` command), never raw levels between cylinders, because the single sensor hears cyl 2/3 loudest.
- Idle duty includes adders: primary fan +2% (3 s after fan on), power steering switch +6%. Check fan status before comparing idle points.
- Fuel pressure channel is gauge pressure: fuel − (MAP − 100) should be ~300 kPa.
- Ignore VVT channels (NB1 has no VVT) and EGT (no sensor fitted).
- Oil pressure in logs before v12 reads high: true ≈ 1.125 × logged − 125 kPa (missing 0.5 V zero point, fixed in v12).
- The first and last sample of every MEITE log are often garbage (e.g. 111–113 °C coolant, 50 kPa oil, 7 V at key-off). Trim ~2 s from each end.
- VE fits: the base calibration must be the one that was in the car when the logs were recorded; write the result into the latest version (`vetools.py fit ... --into`).

## Public repo: no PII or secrets

This repo is public (github.com/chizr/mx5-tune). Everything committed, including history, is readable by anyone and can't be fully withdrawn.

- Never commit: passwords, API keys, tokens or other credentials; addresses, phone numbers, or email addresses other than the commit author; VIN, registration plate, 10th Anniversary build number, or ECU/part serial numbers; names of other people; or work (EstimateOne) details.
- Logs: before adding one, check its header for GPS / latitude / longitude / position channels and drop those columns (or don't commit the log). Note anything removed in `logs/README.md`. Describe where a drive happened generally ("closed road", "street"), never by location.
- Calibrations: check `<CalibrationNotes>` is empty or free of personal details.
- Photos, dyno sheets, receipts and invoices often show plates, names or addresses. Don't commit them unless they're cropped or redacted.
- Commits use `me@christopherdyer.net` (set in this repo's local git config). Never commit with a work email.
- If something sensitive does get committed, stop and tell Chris before pushing. If it's already pushed, rotate any secret first; deleting the file in a new commit doesn't remove it from history.

Chris wants to understand cause and effect, not just get numbers. Explain why a change should help and what log signature would confirm it. Keep changes small and testable before the dyno.
