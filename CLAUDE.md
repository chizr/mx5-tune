# MX-5 NB turbo tune — notes for Claude Code

Chris's NB1 MX-5 10th Anniversary (6-speed; built 1.8 BP, **stock pistons**, forged rods, freshly honed and blueprinted; TD04HL-19T, ME442 ECU, 98 RON). This repo holds the ECU calibration, logs and the worklog. Read `docs/worklog.md` first: hardware, change log, findings, open items and reference numbers all live there.

## Layout

- `calibrations/mx5_nb_me442_vN.mecal` — one file per calibration version, so Chris can see exactly which version he is loading into MEITE. Each new version is a **new file** with the next `vN` suffix, copied from the previous version and then edited; never edit an existing version's file. Each version is also a git commit and tag `vN`. Versions v1–v9 exist only as tags (`git show v7:calibrations/mx5_nb_me442.mecal`); from v10 on there is a file per version.
- `logs/` — ECU logs, renamed `YYYY-MM-DD_HHMM_<source>_<what>.csv`. Index them in `logs/README.md` (calibration tag in the car, fuel age, what was tested).
- `docs/worklog.md` — the living record. `docs/run-sheet_vN.pdf` — printable test plan, generated by `tools/make_runsheet.py`.
- `tools/mecal.py` — read, diff and edit .mecal files. `tools/logtools.py` — load and analyse logs.

## Rules for calibration edits

1. Make a new version with `tools/mecal.py`: `load` the previous `_vN` file, edit with `set_param` / `set_cells`, then `save` to the new `_vN+1` path. It replaces values as text and keeps every other byte, including CRLF line endings. Never re-serialise the XML or reformat the file.
2. Before committing, run `python3 tools/mecal.py diff calibrations/mx5_nb_me442_vN.mecal calibrations/mx5_nb_me442_vN+1.mecal` and check that only the intended values changed. Report that diff to Chris.
3. One logical change set per commit, tagged `vN`. Add rows to the change log table in `docs/worklog.md` in the same commit (tag, area, setting, before, after, why).
4. Chris burns calibrations himself in MEITE after spot-checking. Never claim a version has been driven until he says so.
5. Some driver settings repeat a name: `EPS: Oil` has two `Enabled` params (temperature, then pressure → `occurrence=1`).
6. 2D tables are flat, row-major: index = row × cols + col. Rows are load (MAP kPa, `input_1`), columns are rpm (`input_0`).

## Safety stance

- Stock pistons: failures are ring lands from detonation. Low-rpm, high-load knock is the main risk; cylinders 2 and 3 showed a knock-like pattern on boost (Dec 2025 log, on the old standard TD04; not yet checked on the hybrid).
- Don't raise boost targets or add timing without log evidence. Prefer removing timing over adding it. Keep over-boost cut, lean, oil and knock protection enabled.
- Treat numbers from forums or guesses as approximate and label them. Recommend dyno with det cans for final timing.
- Road testing: full-throttle pulls belong on a closed road, track or dyno.

## Working with logs

- Load with `tools/logtools.load()` (pandas `index_col=False`; data rows end with a trailing comma and PC-log headers have leading spaces).
- 10 Hz typical. Useful commands: `logtools.py summary|lambda|knock|idle LOG`.
- Per-cylinder knock: compare each cylinder against its own light-load baseline (`knock` command), never raw levels between cylinders, because the single sensor hears cyl 2/3 loudest.
- Idle duty includes adders: primary fan +2% (3 s after fan on), power steering switch +6%. Check fan status before comparing idle points.
- Fuel pressure channel is gauge pressure: fuel − (MAP − 100) should be ~300 kPa.
- Ignore VVT channels (NB1 has no VVT) and EGT (no sensor fitted).

## Public repo: no PII or secrets

This repo is public (github.com/chizr/mx5-tune). Everything committed, including history, is readable by anyone and can't be fully withdrawn.

- Never commit: passwords, API keys, tokens or other credentials; addresses, phone numbers, or email addresses other than the commit author; VIN, registration plate, 10th Anniversary build number, or ECU/part serial numbers; names of other people; or work (EstimateOne) details.
- Logs: before adding one, check its header for GPS / latitude / longitude / position channels and drop those columns (or don't commit the log). Note anything removed in `logs/README.md`. Describe where a drive happened generally ("closed road", "street"), never by location.
- Calibrations: check `<CalibrationNotes>` is empty or free of personal details.
- Photos, dyno sheets, receipts and invoices often show plates, names or addresses. Don't commit them unless they're cropped or redacted.
- Commits use `me@christopherdyer.net` (set in this repo's local git config). Never commit with a work email.
- If something sensitive does get committed, stop and tell Chris before pushing. If it's already pushed, rotate any secret first; deleting the file in a new commit doesn't remove it from history.

## Working style

Chris wants to understand cause and effect, not just get numbers. Explain why a change should help and what log signature would confirm it. Keep changes small and testable before the dyno.
